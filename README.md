# MeetMemo

Локальная стенография встреч для Windows 11. Приложение живёт в трее: по горячей клавише
вы выбираете окно встречи, оно раздельно захватывает микрофон и звук этого приложения,
**ведёт стенограмму на русском в реальном времени** и складывает всё в папку встречи.
Готовый пакет можно одним архивом отдать Claude — или любой другой модели — и получить мемо.

Звук и стенограмма никуда не уходят: распознавание работает на вашем компьютере.
Единственная передача данных — ZIP-архив, который вы загружаете в чат сами.

## Демонстрация

**[Посмотреть демонстрацию, как установить и как это работает →](https://xpyctuwe.github.io/MeetMEMO/demo/)**

Анимированная страница проводит весь путь за 24 шага: от скачивания репозитория до
готового мемо. Каждый шаг с пояснением, по шагам можно прыгать.
Ничего устанавливать не нужно — открывается в браузере.

Исходник страницы лежит в [`docs/demo/`](docs/demo/) и работает локально: откройте
`docs/demo/index.html` двойным щелчком.

## Функционал

- Захват звука выбранного приложения (WASAPI process loopback по дереву процессов)
  с автоматическим переходом на общий системный звук, если изоляция недоступна
- Захват микрофона; запись обеих дорожек в WAV — отключаемая настройка
- Живая стенограмма на русском: sherpa-onnx + GigaAM v2, нарезка речи через Silero VAD,
  дозапись `transcript.jsonl` по ходу встречи
- Финальный уточняющий проход по сохранённому аудио (Whisper.net) — даёт пунктуацию и заглавные
- Снимки целевого окна (вручную и автоматически по интервалу + изменению кадра),
  снимок рабочего стола только вручную
- Плавающая панель поверх окна встречи: не забирает фокус и не попадает в собственные снимки
- Кнопки записи прямо в заголовке окна отмеченного приложения: свёрнуты до маленького
  значка, разворачиваются при наведении курсора
- Глобальные горячие клавиши, работающие поверх Teams и браузера
- Восстановление пакета после аварийного завершения приложения
- Сборка ZIP с предварительным показом состава
- Claude Skill `meeting-memo` для превращения пакета в мемо

## Значок приложения

Иконки собираются из `ico.png` в корне проекта:

```powershell
pwsh -File tools/make-icons.ps1
```

Получаются `app.ico` (7 размеров, от 16 до 256 — для панели задач, проводника
и переключателя окон) и три значка для области уведомлений: обычный, с красной точкой
во время записи и с жёлтой на паузе. Точка занимает чуть больше трети значка —
различима даже в 16 пикселях, но логотип не закрывает.

После замены `ico.png` запустите скрипт и пересоберите приложение.

## Требования

- Windows 11 x64 (нужен process loopback; на Windows 10 2004+ основной контур тоже работает)
- ~1 ГБ на диске под модели распознавания
- .NET 8 SDK — ставить заранее не нужно, `publish.cmd` предложит сделать это сам

Компилятор живёт в SDK, а не в Runtime, поэтому для сборки нужен именно он. Если SDK
не найден, `publish.cmd` спросит разрешения и поставит его через
`winget install Microsoft.DotNet.SDK.8` — без прав администратора, один раз.
Если winget недоступен, скрипт даст ссылку на
[ручную установку](https://dotnet.microsoft.com/download/dotnet/8.0).

Собранное приложение автономно — .NET внутри, на других компьютерах ставить не нужно ничего.

## Запуск

Самый простой способ — двойной щелчок по **`MeetMemo.bat`** в корне проекта.
Он находит собранное приложение (сначала в `dist\`, затем в `bin\`) и запускает его.
Окно не появится: MeetMemo живёт в области уведомлений, значок справа внизу.

Собрать готовый к раздаче дистрибутив:

```bash
publish.cmd
```

Получится папка `dist\MeetMemo\` с `MeetMemo.exe` и ярлыком `dist\MeetMemo.lnk`.
По умолчанию сборка автономная — .NET внутри, устанавливать ничего не нужно (~210 МБ).
Вариант полегче, если .NET 8 Desktop Runtime уже стоит:

```bash
publish.cmd -Portable
```

## Сборка из исходников

```bash
dotnet build MeetMemo.sln -c Release
```

```bash
dotnet run --project src/MeetMemo.App -c Release
```

Модели распознавания приложение предложит скачать при первом запуске (~230 МБ).
Проверить их можно через меню значка в трее → «Проверить модели распознавания».

Тесты:

```bash
dotnet test tests/MeetMemo.Tests
```

Проверка распознавания на готовом WAV-файле:

```bash
dotnet run --project tools/AsrSmoke -- путь/к/файлу.wav
```

Сквозная проверка контура (запись → стенограмма → пакет → ZIP) без интерфейса:

```bash
dotnet run --project tools/E2ESmoke -c Release -- 25
```

## Горячие клавиши

| Комбинация | Действие |
|---|---|
| `Ctrl+Alt+M` | Начать запись активного окна / завершить встречу |
| `Ctrl+Alt+P` | Пауза / продолжить |
| `Ctrl+Alt+S` | Снимок целевого окна |
| `Ctrl+Alt+D` | Снимок рабочего стола |
| `Ctrl+Alt+I` | Маркер «Важно» со снимком |

Комбинации сознательно выбраны обычными: клавиша Copilot есть далеко не на всех клавиатурах.
Если комбинация занята другим приложением, MeetMemo сообщает об этом явно, а не молчит.

## Запись всего звука системы

Если встреча идёт в браузере, сразу в нескольких приложениях или искать нужное окно
некогда — в меню значка есть пункт **«Записать весь звук системы»**. Он пишет всё, что
звучит на компьютере, плюс микрофон, без привязки к окну.

Плата за удобство — отсутствие изоляции: в дорожку попадёт и музыка, и звук уведомлений.

Окна-цели у такой записи нет, поэтому вместо значка в заголовке появляется плавающая
панель поверх экрана: таймер, кнопка снимка всего рабочего стола, «Пауза», «Важно»
и «Стоп». Её можно перетащить мышью — положение запоминается. В снимки она не попадает.
Управление доступно и из меню значка в трее, и горячими клавишами.

## Отмеченные приложения

Меню значка в трее → **«Приложения и параметры записи»**. У каждого приложения есть
колонка «Вести»: отметьте те, в которых проходят встречи (Teams, TrueConf, Zoom, браузер),
и нажмите «Сохранить». В заголовках их окон появится маленький значок MeetMemo. Наведите
на него курсор: развернётся управление записью — «Записать», а во время встречи ещё
«Пауза», «Снимок» и «Важно».

Само это окно запись не начинает — оно только сохраняет параметры. Запись всегда
запускается из заголовка конкретного окна, чтобы было видно, что именно пишется.

Снимки сохраняются с палитрой в 64 цвета, подобранной под каждый кадр: файл выходит
в семь раз меньше (5,7 МБ → 0,8 МБ на кадре 3440×1392), а текст остаётся резким —
в отличие от JPEG, который размывает именно буквы. Дизеринг намеренно отключён: на снимке
экрана он превращает ровные заливки в шум, который PNG уже не может сжать, и файл
получается вдвое больше. Настройка `screenshot_colors`: опустите до 32, если места жаль
(будет в девять раз меньше исходного), 0 отключает уменьшение палитры совсем.

Значок сам показывает состояние: серый — готов, красный — идёт запись, жёлтый — пауза.
Отметка действует на приложение целиком и сохраняется между запусками.

**Значок перетаскивается.** У каждого приложения свои кнопки слева от системных, и единого
правильного места не бывает: у Яндекс Браузера это аватар профиля, у других — что-то своё.
Потяните значок мышью влево или вправо — расстояние до правого края запомнится и применится
ко всем окнам. Значок виден только на активном окне: иначе при нескольких отмеченных
приложениях значки просвечивали бы сквозь всё, что открыто поверх.

Во время записи слева от значка появляется кнопка снимка — нажимается сразу, разворачивать
панель не нужно. В самой панели есть галочка «Автоснимки экрана»: её можно снять посреди
встречи, когда на экране появляется лишнее, и вернуть обратно. Выбор запоминается.

## Кто говорит

После остановки записи MeetMemo фоном различает собеседников по голосу: pyannote находит,
где кто-то говорит, отпечатки голосов (3D-Speaker) группируют находки в «Собеседник 1, 2, …».
Ваш микрофон в этом не участвует — он и так отдельная дорожка, целиком ваша.

В `transcript.jsonl` у реплик появляется поле `speaker` («spk1», «spk2»), в `transcript.md` —
«Собеседник N» вместо безликого «Приложение». Это метки тембров, а не имена: имя модель,
собирающая мемо, привязывает по самой речи — обращениям и представлениям.

**Имена берутся из окна встречи.** Параллельно MeetMemo раз в полминуты снимает текст,
видимый в окне: список участников, сообщения чата, тему. Это дерево доступности — то же,
что озвучивают программы экранного доступа, а не разбор вёрстки и не перехват сети.
Пишется в `context.jsonl`, только когда текст изменился. Chromium (Chrome, Edge, Яндекс
Браузер, Electron) строит это дерево лениво, поэтому приложение сначала представляется
клиентом доступности — иначе снаружи видно полтора десятка пустых панелей вместо страницы.

Содержимое самого звонка из сети вытащить нельзя и не пытаемся: WebRTC шифрован
(DTLS-SRTP). Голос берётся из аудиопотока, имена — из интерфейса. Выключается настройкой
`collect_window_context`.

Разметка идёт в фоне (час записи — порядка десяти минут на процессоре) и по завершении
показывает уведомление. Если собрать ZIP раньше, пересоберите его из «Последних встреч» —
станет с разметкой. Считывать говорящего из интерфейса встречи мы сознательно не стали:
у каждого приложения своя вёрстка, и каждое обновление её ломает — голос надёжнее.

## Пакет встречи

```
2026-07-31_1430_Совещание/
├── session.json          параметры встречи
├── timeline.jsonl        события с таймкодами
├── transcript.jsonl      стенограмма построчно
├── transcript.md         читаемая версия
├── glossary.md           словарь терминов (заполняете вы)
├── audio/                дорожки, если включено сохранение
├── screenshots/          снимки + index.json
├── diagnostics/          журналы
└── output/               сюда кладёте результаты Skill из Claude
```

Все форматы открытые: JSON, JSONL, Markdown, WAV, PNG. Пакет читается без MeetMemo.

При сборке ZIP в корень архива добавляются ещё два файла: `КАК_ИСПОЛЬЗОВАТЬ.md` —
что внутри и чего ждать от автоматической стенограммы, и `!ИНСТРУКЦИЯ_ДЛЯ_CLAUDE.md` —
правила составления мемо.

## Как получить мемо

1. В карточке завершения нажмите «Собрать ZIP».
2. Загрузите архив в чат с моделью и отправьте.

Писать запрос не нужно: правила обработки вложены в каждый архив файлом
`!ИНСТРУКЦИЯ_ДЛЯ_CLAUDE.md` — модель прочитает его и приступит сама. На выходе:

- `memo.docx` — мемо документом Word, решения и поручения таблицей;
- `memo.md` — то же текстом;
- `transcript_clean.md` — вся речь, разобранная по темам и говорящим, с разделом
  «Спорные места»: видно, что распозналось надёжно, а что стоит перепроверить;
- `actions.json` — поручения списком.

Правила требуют писать «не определён» вместо догадки об ответственном, ставить таймкод
у каждого решения и не выдавать обсуждение за решённое.

Тот же текст доступен как Skill `meeting-memo` (папка `skill/`) — его можно поставить
в Claude, если удобнее вызывать обработку по имени. Шаблон вшивается в сборку, поэтому
после правки файлов в `skill/meeting-memo/` проект нужно пересобрать.

**Claude не обязателен.** Название файла с инструкцией историческое: внутри архива только
открытые форматы, а правила написаны обычным текстом. Подойдёт любая модель, которая
умеет принимать файлы, — ChatGPT, Gemini, YandexGPT, GigaChat, локальная через Ollama.
Разница будет в дисциплине: чем хуже модель держит инструкцию, тем чаще придётся
проверять, не выдумала ли она ответственного вместо честного «не определён».

## Известные ограничения

- **Стенограмма идёт без пунктуации и заглавных букв.** Так работает GigaAM — лучшая
  открытая русская модель по точности слов. Читаемый текст даёт финальный проход Whisper
  и мемо, собранное в Claude.
- **Изоляция звука работает по процессу, а не по окну.** У браузеров в дорожку может попасть
  звук другой вкладки того же процесса — приложение предупреждает об этом при выборе браузера.
- **Исключение панели из снимков — best effort.** `WDA_EXCLUDEFROMCAPTURE` не является DRM
  и не гарантирует невидимость во всех способах записи экрана.
- **Свёрнутое окно не отдаёт кадры.** Автоснимки на это время приостанавливаются,
  запись звука продолжается.
- Финальный проход требует включённого сохранения аудио — пересчитывать иначе нечего.

## Правовое напоминание

Предупреждайте участников о записи и соблюдайте правила вашей организации
и применимое законодательство. Во время записи всегда видны красный значок в трее
и панель с таймером — скрытой записи в продукте нет.
