# Архитектура MeetMemo

## Структура решения

```
src/
├─ MeetMemo.Contracts   схемы пакета встречи (session, timeline, transcript, screenshots)
├─ MeetMemo.Core        SessionController, ISessionClock, деградация, контракты подсистем
├─ MeetMemo.Storage     JsonlWriter, атомарная запись, папка встречи, восстановление
├─ MeetMemo.Audio       WASAPI: микрофон, process loopback, системный loopback, запись WAV
├─ MeetMemo.Capture     перечисление окон, снимки, автоснимки, горячие клавиши
├─ MeetMemo.Asr         живая стенограмма (sherpa-onnx) и финальный проход (Whisper.net)
├─ MeetMemo.Export      состав пакета и сборка ZIP
└─ MeetMemo.App         WPF: трей, панель, выбор источника, карточка завершения

tools/
├─ AsrSmoke             распознавание готового WAV, замер real-time factor
└─ E2ESmoke             сквозной прогон сессии без интерфейса

tests/MeetMemo.Tests    модульные и интеграционные тесты
skill/meeting-memo      Claude Skill для превращения пакета в мемо
```

## Ядро: SessionController

Все команды — из трея, с плавающей панели и от горячих клавиш — попадают в один
`Channel<SessionCommand>`, который разбирает единственный потребитель. Поэтому гонок
между источниками команд не возникает по построению, а недопустимые переходы состояний
отклоняются в одном месте.

Подсистемы подключаются как `ISessionParticipant` и останавливаются по возрастанию
`StopOrder` с таймаутом на каждую:

| Подсистема | StopOrder | Почему так |
|---|---|---|
| Снимки | 50 | наименее ценны, останавливаются первыми |
| Распознавание | 90 | должно успеть дослать последнюю фразу |
| Аудио | 100 | запись звука ценнее всего, закрывается последней |

Зависшая подсистема не блокирует остановку остальных: по таймауту она пропускается,
а в пакет попадает предупреждение, и сессия получает статус `completed_with_warnings`.

## Время

`ISessionClock` — единственный владелец шкалы. Относительные таймкоды считаются от
`Stopwatch.GetTimestamp()`, поэтому перевод системных часов во время встречи не нарушает
порядок событий. Пауза не останавливает шкалу: разрыв фиксируется событиями
`recording_paused` / `recording_resumed`, а таймкоды остаются сопоставимыми со снимками.

## Путь звука

```
WASAPI (микрофон)      ─┐
WASAPI (loopback окна) ─┴─► AudioEngine ─┬─► WaveFileTap    → audio/*.wav (опция)
                                          ├─► AsrFeeder      → 16 кГц моно
                                          └─► индикаторы     → уровни на панели
                                                  │
                                        Silero VAD (нарезка фраз)
                                                  │
                                          очередь сегментов
                                                  │
                                     GigaAM v2 (один поток)
                                                  │
                                          transcript.jsonl
```

Потребители звука делятся на критичные и нет. Запись на диск критична — её порции
не выбрасываются никогда. Распознавание некритично: при перегрузке очередь дропает
самые старые сегменты, потому что свежий текст на экране полезнее опоздавшего,
а пропуск в аудиозаписи невосполним.

## Почему два движка распознавания

- **Живой проход — GigaAM v2 через sherpa-onnx.** Лучшая открытая точность на русском,
  RTF около 0.12 на CPU (замерено), GPU не нужен. Не даёт пунктуации и заглавных букв.
- **Финальный проход — Whisper large-v3-turbo через Whisper.net.** Медленнее, но возвращает
  читаемый текст с пунктуацией и лучше обрабатывает англоязычные термины. Работает офлайн
  по сохранённому аудио, поэтому скорость там некритична.

Черновая стенограмма при финальном проходе сохраняется рядом как `transcript.live.jsonl`:
на терминах живая модель иногда точнее.

## Устойчивость к аварийному завершению

- `transcript.jsonl` и `timeline.jsonl` пишутся построчно со сбросом на диск не реже 5 секунд;
  оборванная последняя строка при чтении отбрасывается, остальное сохраняется
- `session.json` и `screenshots/index.json` пишутся атомарно (временный файл + переименование)
  с ретраями — антивирус и клиенты облачной синхронизации периодически держат файлы открытыми
- WAV пишется с файлом-меткой длины: после аварии заголовок восстанавливается по нему
- `session.lock` с PID отличает живую сессию от брошенной; при следующем запуске
  приложение находит незакрытые встречи и предлагает восстановить пакет

## Приватность по построению

- Снимок окна делается через `PrintWindow` с полным рендерингом: перекрывающие окна
  и уведомления в кадр не попадают
- Снимок рабочего стола — только по явной команде, автоматически никогда
- Панель исключается из захвата через `SetWindowDisplayAffinity`; механизм best effort
  и в документации не выдаётся за гарантию
- Сеть используется только для загрузки моделей по явному действию пользователя
- В журналы не попадают текст стенограммы, содержимое снимков и аудиоданные
