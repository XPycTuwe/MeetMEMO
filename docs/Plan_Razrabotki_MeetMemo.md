# План разработки MeetMemo (по ТЗ v1.1)

Дата: 31.07.2026. Основа: ТЗ v1.1 (23 приёмочных сценария AC-01..AC-23, этапы 21.1) и пять доменных планов (аудио, окно/снимки/overlay/хоткеи, ASR, сессия/данные, трей-UI/Skill). Все оценки — идеальные рабочие дни соло-разработчика с ИИ-ассистентом (Claude Code), диапазоном.

**Модель распространения:** сначала личное использование (dogfooding — ядро плана), затем публикация в open source на GitHub (лицензия MIT). Все выбранные зависимости и модели MIT/Apache-2.0 — совместимы; обязательство одно: THIRD-PARTY-NOTICES с текстами лицензий в репозитории. Модели в git не кладутся — их скачивает ModelManager (4.8) с проверкой SHA-256.

## 1. Резюме

**Что строим.** Windows 11 x64 трей-приложение: по глобальной горячей клавише пользователь выбирает окно встречи (Teams/Zoom/Telegram/браузер), приложение раздельно захватывает микрофон и звук дерева процессов (WASAPI application loopback), ведёт **живую русскоязычную стенограмму** с непрерывной дозаписью в `transcript.jsonl` (flush ≤ 5 с), делает ручные и автоматические снимки целевого окна (WGC + dHash-дедупликация), показывает плавающую панель, исключённую из захвата (WDA_EXCLUDEFROMCAPTURE), и по завершении собирает самодостаточный пакет встречи + ZIP для ручной передачи в Claude Skill `meeting-memo`. Никакого API, никакой сети, кроме явной загрузки ASR-модели.

**Главный принцип очередности** (ТЗ 22.1): сначала *доказать*, потом строить. Два PoC-этапа закрывают все архитектурные ставки до начала Core MVP:
1. Этап 1 доказывает захват: изоляция process loopback на реальных Teams/Chrome/Edge, WGC-захват HWND при DPI/ресайзе, overlay без кражи фокуса, WDA-исключение — и фиксирует выбор WPF vs WinUI 3 (ADR).
2. Этап 2 доказывает live-ASR на ГОТОВЫХ движках с GitHub: sherpa-onnx (NuGet, in-process) с русской моделью GigaAM v2 на CPU + Whisper.net для финального прохода — замер RTF, качества русского и читаемости на собственных записях встреч. Никакой самодельной обвязки OpenVINO GenAI C API.

Всё остальное (автоснимки, финальный проход, ZIP, Skill) — независимые модули, не имеющие права остановить основной контур «аудио → стенограмма → восстановление».

**Порядок исполнения — вертикальный срез, а не этапы подряд.** Ядро продукта — живая стенограмма; ждать её до конца полного этапа 3 нельзя. Поэтому после блоков 3.1–3.3 (каркас, Session Controller, аудиотракт) сразу выполняются задачи 4.1–4.6 (ASR-воркер, VAD, live transcript.jsonl, CPU fallback) с минимальным запуском из трея и хоткея — получается **«MeetMemo-lite»** (микрофон + process loopback + живая стенограмма, без панели и пикера) примерно на **50–75-й идеальный день**. Дальше — **dogfooding-гейт**: 3–5 реальных встреч записываются самим разработчиком; только после этого строятся капчур/overlay/UI (блоки 3.4–3.5), остаток этапа 4 (мастер, ModelManager) и этапы 5–6. Формальная нумерация этапов ТЗ 21.1 сохраняется — срез оформляется как ранний интеграционный прототип внутри этапов 3–4 (согласовать с заказчиком).

Календарная последовательность: `0 → 1 → 2 → 3.1 → 3.2 → 3.3 → 4.1–4.6 [MeetMemo-lite + dogfooding] → 3.4 → 3.5 → 4.7–4.11 → 5 → 6 → 7`.

**Ключевые архитектурные решения** (обоснованы в разд. 4):
- ASR — два готовых движка с GitHub, оба in-process через NuGet, факты проверены 31.07.2026: **live = sherpa-onnx** (`org.k2fsa.sherpa.onnx` 1.13.4 от 08.07.2026, Apache-2.0, 13.9k звёзд, встроенный Silero VAD, официальные C#-примеры) с моделью **GigaAM v2 CTC int8** (Сбер, MIT, конвертация 2025-04-19, лучший открытый русский WER, RTF ~0.33 на CPU — GPU не нужен, CPU-fallback из ТЗ становится основным режимом); **финальный проход P1 = Whisper.net** (1.9.1 от 01.06.2026, MIT, whisper.cpp под капотом) с large-v3-turbo — пунктуация, регистр и англо-русский code-switching, Vulkan-runtime задействует Arc B390. Самодельная обвязка OpenVINO GenAI C API не нужна вовсе.
- Единый Session Controller-актор (`Channel<SessionCommand>`, один потребитель) — защита от гонок панели/хоткеев/трея (ТЗ 7.3).
- UI-фреймворк: **WPF на .NET 8** как рабочая гипотеза; окончательно — ADR после PoC overlay/DPI (ТЗ 14.3 допускает). Архитектурный референс двухканального захвата и live-конвейера — Meetily (Zackriya-Solutions/meeting-minutes, MIT, 27.6k звёзд: одновременный захват микрофона и системного звука на Windows).

**Общая оценка** (честная сумма задач по этапам, после дедупликации доменных пересечений):

| Объём | Идеальные дни |
|---|---|
| Полный план (этапы 0–7, включая P1-блок этапа 7) | **≈ 108.5–166.5** |
| Только P0-ядро (без истории встреч, просмотра стенограммы, финального прохода) | ≈ 102.5–156.5 |
| «MeetMemo-lite» (первая живая стенограмма реальной встречи) | ≈ 50–75 |

При устойчивых 4–4.5 идеальных днях в неделю это **≈ 6–9.5 календарных месяцев** соло-работы до полного MVP; рабочий продукт для собственных встреч — через **~3–4 месяца**. Переход на готовые движки (sherpa-onnx + Whisper.net вместо самодельной OpenVINO-обвязки) снял ~7–10 дней с этапов 2 и 4. Доменные разделы декларировали «итого» ниже своих собственных сумм задач (напр., capture: заявлено 21–29, сумма задач 24.5–33); здесь взяты суммы задач — по правилу «не занижать» (в т.ч. пересчитаны заголовки этапов 1 и 3 после критики: сумма > первоначально заявленной).

## 2. Этап 0 «Окружение» — чек-лист (1–2 дня)

На машине нет ни Python, ни Node — и они **не нужны**: весь стек — .NET 8 + NuGet + готовые модели с Hugging Face (конвертации sherpa-onnx и ggml). Порядок установки:

1. **Visual Studio 2022** (17.10+), workload «.NET desktop development» (+ «Desktop development with C++» — опционально, пригодится только для отладки нативных крашей). Компоненты: Windows 11 SDK 10.0.22621+.
2. **.NET 8 SDK** — ставится с VS; проверить `dotnet --list-sdks` (нужен 8.0.4xx).
3. **Git for Windows** + инициализация репозитория `MeetMemo` (сейчас каталог не под git); `.gitignore` для .NET; репозиторий держать **вне OneDrive-синхронизации** (см. риск R-06) — например `D:\Dev\MeetMemo`, рабочие данные Meetings — тоже.
4. **ASR-движки — готовые NuGet, никаких SDK-архивов**: `org.k2fsa.sherpa.onnx` 1.13.x (тянет свой нативный рантайм win-x64 автоматически) и `Whisper.net` 1.9.x + `Whisper.net.Runtime` (CPU) + `Whisper.net.Runtime.Vulkan` (win-x64, для Arc в финальном проходе). Смоук за полчаса: официальные C#-примеры sherpa-onnx из `dotnet-examples/` (vad-non-streaming-asr) на любом WAV. OpenVINO Toolkit НЕ ставить — он больше не нужен.
5. **Драйвер Intel Arc** (Xe3/B390): обновить до последнего WHQL (нужен только для Vulkan-ускорения финального прохода; live-контур — чистый CPU); зафиксировать версию в отчёте PoC.
6. **Модели** (все готовые, конвертация не нужна; скачать в `%LOCALAPPDATA%\MeetMemo\models`, зафиксировать SHA-256):
   - live: **GigaAM v2 CTC int8** — официальная конвертация `sherpa-onnx-nemo-ctc-giga-am-v2-russian-2025-04-19` (226 МБ, MIT) + RNNT-вариант для сравнения. **Лицензионный капкан: v1-архивы `giga-am-russian-2024-10-24` — только некоммерческое использование, в дистрибутив не класть ни при каких условиях; брать строго v2 (2025-04-19)**. GigaAM v3-конвертации (csukuangfj, 2025-12-16) — скачать как кандидата на апгрейд, но они вне официальных релизов sherpa-onnx («серый» статус);
   - live-альтернатива для сравнения: `sherpa-onnx-streaming-t-one-russian-2025-09-08` (Т-Банк, Apache-2.0, честный стриминг, но телефонный домен 8 кГц);
   - финальный проход: ggml `large-v3-turbo-q5_0` (574 МБ) и `q8_0` (874 МБ) с huggingface.co/ggerganov/whisper.cpp (MIT);
   - VAD: Silero VAD встроен и в sherpa-onnx, и в Whisper.net 1.9.1 — отдельно не нужен.
7. **Windows App SDK** — НЕ ставить заранее: при выборе WPF unpackaged он не нужен (WinRT-проекция WGC встроена в TFM `net8.0-windows10.0.22621.0`). Ставится только если ADR выберет WinUI 3.
8. **Вспомогательное**: HWiNFO64 (CSV-лог температур/мощности для бенчмарков), 7-Zip (проверка ZIP), `flac.exe` только для локальных экспериментов (утилита — **GPLv2+**; в поставку — libFLAC (BSD) через P/Invoke или managed-энкодер, см. 3.3.8), Inno Setup (этап 7).
11. **Code-signing**: для личного использования подпись не нужна — пункт не блокирует ничего. Для публичных релизов на GitHub: бесплатная программа SignPath для open-source проектов (заявку подать заранее — рассмотрение занимает время) либо жить с предупреждением SmartScreen (обычная практика молодых OSS-проектов). Покупка OV/EV-сертификата — только если появится коммерческая дистрибуция.
9. **NuGet-набор** (зафиксировать версии в Directory.Packages.props): `org.k2fsa.sherpa.onnx`, `Whisper.net` + `Whisper.net.Runtime` + `Whisper.net.Runtime.Vulkan`, `Microsoft.Windows.CsWin32`, `NAudio` 2.2.x, `Vortice.Windows` (D3D11), `CommunityToolkit.Mvvm`, `Hardcodet.NotifyIcon.Wpf` (или `H.NotifyIcon.Wpf`), `Microsoft.Extensions.Hosting`, `Serilog` + `Serilog.Sinks.File`, `JsonSchema.Net`, `Microsoft.Extensions.TimeProvider.Testing`, xUnit + FluentAssertions. (`Microsoft.ML.OnnxRuntime` отдельно НЕ ставить — sherpa-onnx несёт свой onnxruntime; два экземпляра в процессе = конфликт нативных DLL.)
10. Эталонные аудиоданные: Common Voice ru (выборка) + план записи 2–3 собственных «технических совещаний» (термины ППД/трубопроводы) — понадобятся на этапе 2.

**Критерий выхода:** подтверждены предпосылки **AC-02, AC-03, AC-04, AC-07, AC-08** на целевом ноутбуке; ADR-001 подписан; список несовместимых приложений (если есть) задокументирован; go/no-go по карте PoC (разд. 5).

```
├─ src/
│  ├─ MeetMemo.Contracts    DTO схем (session/timeline/transcript/index/actions),
│  │                        SessionStatus, события 11.2, JsonSerializerContext
│  ├─ MeetMemo.Core         SessionController (актор), ISessionClock, шина событий,
│  │                        DegradationPolicy, ISessionParticipant
│  ├─ MeetMemo.Storage      JsonlWriter, AtomicJsonStore, MeetingFolderFactory,
│  │                        RecoveryService, DiagnosticsWriter, монитор диска
│  ├─ MeetMemo.Audio        WASAPI: mic / ProcessLoopbackCapture / system fallback,

│  ├─ MeetMemo.Capture      WGC interop, WindowCaptureService, WindowEnumerator,
│  │                        WindowTracker, ScreenshotStore, AutoSnapshotPolicy
│  ├─ MeetMemo.Asr          sherpa-onnx (OfflineRecognizer + Silero VAD, GigaAM v2) —
│  │                        live; Whisper.net (large-v3-turbo, Vulkan/CPU) — финальный
│  │                        проход; SegmentQueue, профили, ModelManager. Всё in-process
│  │                        (вынос в отдельный процесс — только по итогам соак-тестов)
│  ├─ MeetMemo.Export       ExportPlanBuilder, ZipPackager, журнал экспорта
│  └─ MeetMemo.App          net8.0-windows (WPF): трей, overlay-панель, пикер,
│                           настройки, мастер, карточка; Generic Host, DI,
│                           HotkeyManager (message-окно)
├─ skill/meeting-memo/      SKILL.md, references/, examples/sample_package/
└─ tests/                   Core/Storage/Export unit; IntegrationTests:
                            kill-harness, дрейф-харнесс, soak, JSON Schema
```

**Session Controller — ядро.** Все команды (трей, панель, хоткеи) идут в один `Channel<SessionCommand>`; подсистемы Audio/Capture/Asr/Storage регистрируются как `ISessionParticipant` со Start/Pause/StopAsync под таймаутами. Ключевые интерфейсы между доменами:

| Интерфейс | Поставщик → потребитель | Назначение |
|---|---|---|
| `ISessionClock` (monotonic_origin, offset_ms) | Core → все | единственная шкала времени (⚠ синтез, разд. 3.2) |
| `ISessionParticipant` | Core → Audio/Capture/Asr | жизненный цикл с таймаутами |
| `IAudioTap` (bounded Channel PCM) | Audio → Storage(DiskWriter)/Asr(AsrFeeder)/UI(Meters) | развязка: диск никогда не дропается, ASR-фреймы — можно |
| `SegmentQueue` (bounded, in-process) | AsrFeeder → Asr | сегменты двух каналов с приоритетом live; изоляция исключений + рестарт распознавателя |
| Шина событий 11.2 | все → Core → TimelineStore | единственный писатель timeline.jsonl |
| `IJsonlWriter`/`IAtomicJsonStore` | Storage → все | flush ≤ 5 с, tmp+rename |
| `DegradationPolicy` сигналы | Core → Capture(автоснимки)/Asr(профиль) | порядок 17.1 |
| `IExportPlan` | Export → App(диалог) | предпросмотр состава ZIP |

Правила изоляции отказов (ТЗ 16): исключения CaptureEngine и ASR не покидают своих доменов (лог + событие + рестарт подсистемы); аудиозапись и JsonlWriter останавливаются последними. Нативная часть ASR — зрелые onnxruntime (sherpa-onnx) и whisper.cpp (Whisper.net), проверенные тысячами продакшн-установок; при крашах в соак-тестах ASR выносится в отдельный процесс (архитектура SegmentQueue это допускает без переделки).
